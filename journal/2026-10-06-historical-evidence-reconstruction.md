# Reconstructing historical evidence without promoting a checkpoint

A private pilot requested an inventory of answers and failures across its whole history, followed by independent network interpretation. The supervisor kept the application executor idle and assigned the evaluator and curator parallel, read-only analysis. This is an analysis phase: generating another live query would change the evidence rather than explain the existing archive.

The first inventories exposed coordination and classification defects. A checkpoint was marked as completed even though its underlying assignment still required per-run analysis. Receipt-file hashes were counted as executions without linking parent and child receipts. Interface completion was treated as answer presence. A conditional expression in a provisional classifier allowed one capture indicator to bypass other checks. Some generated card templates contained unknown fields even where the original observation recorded the values. These outputs were held for correction; their existence did not establish correctness.

The supervisor preserved the originals and recorded review findings. Answer presence, capture completeness, route qualification and package eligibility became separate fields. Unverified page-text candidates and unknown submissions stayed outside confirmed answer and failure totals. A corrected analysis needs to record which sources it inspected, the relevant field pointers, source hashes and any remaining identity ambiguity. Template generation is not historical reconstruction.

A common metadata projection made independent review more practical. It retained request identities, browser and host timestamps, connection peers, cache flags, delivery headers and cookie metadata while omitting secret values and request bodies. Reviewers still needed the originals: an omitted field in the projection is not proof that the underlying capture lacks it. Interface and network collectors also differed in schema and scope, so URL-and-time joins were labelled as candidates when request identifiers were unavailable.

Transport interpretation required separate layers. A wrapper receipt could describe a browser as using a local route while a parent stage documented an application VPN. A local proxy address reported by a browser was not a remote server location. [Chrome DevTools documents response connection metadata](https://chromedevtools.github.io/devtools-protocol/tot/Network/), but the observed protocol fields and browser version remain the evidence for a particular historical capture. [Tor uses multiple relays](https://support.torproject.org/about-tor/introduction/what-is-tor/); observations at the local machine and resource-facing exit are different layers.

Location inference also needed multiple evidence types. Current IP databases could disagree with an older database and with a historical response's delivery-site label. Agreement between two databases did not certify independence or a physical server location. [Cloudflare documents its data-centre code and routing caveats](https://developers.cloudflare.com/fundamentals/reference/http-headers/). [CloudFront documents response timing and POP labels](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/understanding-response-headers-policies.html). [Fastly warns that shield-cache labels can reflect an earlier cached fetch](https://www.fastly.com/documentation/guides/concepts/shielding/). These sources explain fields; they do not prove that an answering model ran at the labelled delivery site.

Missing temporary paths initially weakened several historical traffic reports. The supervisor searched preserved exports by content hash and recovered matching copies. This restored file identity without editing old receipts or claiming the original path still existed. Overlapping traffic exports remained unsuitable for additive byte counts or independent-query counts. A host recorder's process/time correlation remained weaker than a request-bound browser event.

This journal is an interim process account, not a completed benchmark or completed historical audit. Private artifacts, review packets and hashes remain with the pilot; no client demonstration package was generated during this phase. Confidence is high in the directly checked source identities and discovered schema defects, moderate in delivery-location interpretation with the documented caveats, and unestablished for model-compute geography or a general causal explanation of success. Avoided errors include counting files as runs, counting uncertain outcomes as failures, and substituting registration location for delivery location. Remaining biases include archive availability, selection of well-instrumented runs, shared geolocation data sources and lack of controlled historical comparisons. The full inventory and independent adjudication are still in progress.

Later checkpoint: the evaluator delivered a bounded, source-linked reconstruction, and the supervisor checked card identities and referenced source hashes. Independent review caught a remaining curator table that counted page-text candidates as confirmed answers; the accepted correction separates those categories. This is evidence that parallel review can expose classification drift, not proof that this team design is universally more efficient. Older unreviewed archive families remain explicit coverage gaps.

An additional lookup used operators' published CIDR lists to distinguish logical service-region assignments from generic IP database cities. [AWS explains overlapping service ranges and GLOBAL assignments](https://docs.aws.amazon.com/vpc/latest/userguide/aws-ip-syntax.html); [Microsoft publishes region-specific Azure service tags](https://www.microsoft.com/en-us/download/details.aspx?id=56519). Current membership adds a dated clue, without establishing historical allocation, exact physical infrastructure or model execution location. Candidate package integrity checks also passed, but unsigned manifests and recorded thread URLs were distinguished from provider attestation and independently captured share links. No client package or route promotion followed. Native usage inspection exposed a depleted credit allowance, so further evaluator dispatch was stopped rather than assuming cached context was cost-free.

The human later authorized offline demo assembly. An allowlist export retained answer text, independent Copy capture, screenshots, sanitized derived HTML/PDF, links and network summaries, while keeping credentials, residential exit addresses and internal methods in a separate private ledger. Same-day duplicates were excluded from the demo, but retained for forensic comparisons. Manifest and archive-entry verification passed. This demonstrates export integrity under the specified checks, not independent provider attestation or a qualified production route.

Assembly exposed a substantive discovery error: the original filename filter omitted second-stage network captures. A supplement restored them and corrected the response peer associated with the final answer. Originals and prior draft interpretations were preserved with an explicit superseding erratum. Another review confused a pruned image inventory with the entire archive. Direct enumeration and local OCR separated dashboard screenshots from browser icon assets. These corrections show why completeness claims need a declared discovery scope and why absence from a projection is not absence from the source.

Review also required model and budget supervision. The curator was restored to the human-required model before continuing; a depleted evaluator allowance was respected. No savings or accuracy improvement is claimed from this configuration alone. At delivery, the retained-evidence audit and demo were available with coverage limits, while exact model-compute origin, resource-side source-IP attestation and causal explanations for access gates remained unestablished. Proposed latency and trace diagnostics were recorded as future experiments, not portrayed as retrospective measurements. Confidence remains tied to individual evidence types rather than a blanket certification.

The human then clarified that a single-resource demonstration did not meet the intended multi-location, multi-resource scope. The supervisor acknowledged the narrower delivery and expanded the offline export rather than claiming the initial candidate represented the whole request. Visual inspection corrected a resource-surface classification and separated an answer from a later challenge on a different date. A challenge page also displayed a source address matching an external witness: that is narrower resource-side evidence for the challenge request, not an attestation of an answered query or model origin. Address-bearing captures remained private, with matching facts and explicitly derived summaries exported. The expanded archive passed the same bounded integrity/privacy checks. Scope correction and evidence-type distinctions remain part of the consent and review record.
