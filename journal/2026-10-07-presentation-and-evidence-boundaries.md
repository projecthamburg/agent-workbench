# Presentation and evidence boundaries

A client usability complaint exposed a capture-order defect: the primary image showed a source dialog covering the answer. The dialog was legitimate evidence of an inspection action, but an unsuitable answer presentation. The remedy preserves originals, captures the completed unobstructed answer before inspecting controls, and retains source-panel captures separately. A reconstructed reading view is explicitly labelled as a reconstruction rather than a provider screenshot.

The supervisor, research executor, evaluator and designer divided the work. The executor repaired capture ordering and diagnostic classification; the evaluator checked source behavior and reviewed exported artifacts; the designer built static resource-specific reading views; the supervisor integrated scoped changes, checked evidence and controlled the live release. Native terminal instructions were mirrored into role mail. A delivery receipt remained a request for review rather than proof of correctness.

Offline checks passed for capture ordering, partial exports and diagnostic separation. This supports implementation behavior under the tested conditions, not universal browser reliability. An independent design review found almost-empty first PDF pages and a missing continuation warning in clean exports. The next revision corrected print pagination and put the warning into HTML, PNG and PDF. Supervisor checks independently verified the bundle hash, first-page text coverage for all clean PDFs, and representative rendered pages. Further independent review remains pending at this entry.

A network-review script repeatedly returned misleading empty results because it assumed a URL string where the capture stored a structured URL object, then swallowed exceptions. The supervisor's corrected parser preserved request identifiers, redirect hops, timestamps, peer addresses and capture gaps. An empty analysis is not evidence of an empty network when the parser has failed. Source-type checks and independently verified counts are necessary before interpreting summaries.

The fresh live launch also stopped before browser activity when two native usage observations disagreed about reset-window identity. A later actual telemetry refresh reconciled the identities. The guard was retained; it was not bypassed. A repeated preflight is distinct from a repeated resource query, and the campaign ledger must establish that distinction.

Public grounding for the methods: [Playwright screenshots](https://playwright.dev/python/docs/screenshots), [Chrome DevTools Protocol Network domain](https://chromedevtools.github.io/devtools-protocol/tot/Network/), [CSS fragmentation specification](https://www.w3.org/TR/css-break-3/), and [Cloudflare response-header documentation](https://developers.cloudflare.com/fundamentals/reference/http-headers/). These describe tool behavior and interpretation constraints; they do not validate this project's delivered artifacts or establish a model backend's location.

Biases addressed: completion-as-correctness, attractive-layout-as-fidelity, word-overlap-as-exact-preservation, expected-location confirmation, and interpreting parser silence as absence. Remaining limitations include sampled visual checks, incomplete historical capture, provider-controlled headers, and an unverified shared-GUI coordination service. Confidence is high for directly hashed artifacts and observed test results, moderate for presentation coverage, and unresolved for hidden model origins. Live capture acceptance is still pending; no production route is promoted by this entry.
