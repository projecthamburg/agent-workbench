# Live evidence, failed captures, and supervision recovery

A private application pilot separated an answer being generated from the evidence package qualifying. One cell recorded a complete answer and its generation-control transition, while the independent Copy interaction failed behind an informational onboarding tip. Another cell verified its requested regional exit but timed out during entry; the saved mutation log recorded a cookie dialog appearing immediately before that phase. These observations justified narrow ordinary-interface repairs. They did not justify bypassing authentication, inventing missing captures, or declaring the causes proven from a screenshot alone.

The executor implemented the application repair; the evaluator reviewed the changed code and focused fixtures; the supervisor integrated only the accepted scope. Changed or ambiguous interface structures remain failures. An ordinary dismissal of a recognized informational tip is a different operation from deleting a login or challenge wall. A generated answer, an independent text capture, a source-list capture, and a qualifying independent replication are separate milestones.

Network records require the same distinctions. External exit witnesses describe the tested outward address. DevTools response peers describe observed connections for particular request IDs. Process/time correlations from a host traffic recorder are a separate kind of evidence. A registry allocation identifies registered address ownership, not a physical data centre, model execution location, response origin or cited authority. An address-ownership match cannot substitute for resource-side confirmation of the client address.

A supervisor monitoring defect also occurred. A registry update omitted acknowledgment deadlines; a later atomic write published permissions incompatible with the monitor's private-file reader. Direct checks continued, but automatic notifications were interrupted. The supervisor restored explicit deadlines and private file permissions and recorded the gap. This is a failure of the coordination implementation, not evidence that recipients ignored messages. See the cooperative monitoring requirements in [supervision](../docs/SUPERVISION.md) and [evidence](../docs/EVIDENCE.md).

Independent review also held a claimed cleanup because run-owned profile files remained after the browser exited. The supervisor preserved those files by atomically moving the exact run-owned directory into a private quarantine, recorded file hashes, and collected fresh baseline witnesses. The original receipt remained unchanged. A new review is required; a handback label or vanished process alone is insufficient.

An uncertain submission remains charged at its reserved upper bound. Closing a reviewed, cleaned-up unknown attempt is not a refund, proof of zero submissions, replay permission, or successful calibration. Further execution requires an explicit bounded authorization against the remaining shared budget.

Evidence basis: private hashed task, UI mutation, network, cleanup and independent-review receipts retained by the pilot project. They are not published here and have not been independently reproduced publicly. This journal reports the pilot process, not a benchmark. Confidence is high for the retained record distinctions and executed focused fixtures, moderate for the inferred obstruction, and unestablished for general improvements in throughput or regional answer effects. Avoided fallacies include equating address ownership with server location, equating answer generation with capture qualification, and equating an attempt counter with accepted submissions. Remaining biases include a small selected sample, supervisor-authored coordination code, changing provider interfaces, and failed or unrun matrix cells.

A further admission failure exposed a monitoring tradeoff: screenshot-heavy native logs can push the latest model/workspace record outside a short tail even when recent usage telemetry remains present. The supervisor separated the bounded search for identity metadata from the smaller fresh-telemetry tail. Independent review exercised the displacement and later-model-change cases. Unknown individual-limit data now holds execution. This is a conservative point-in-time gate, not a billing oracle, continuous spending guarantee, or universal enforcement for older launch formats.

A prepared release also encountered a human pause before its visible relay. The supervisor withheld the release, stopped the existing campaign without resetting charges, and archived its pending acknowledgment watch rather than fabricating a recipient acknowledgment. Delayed completion notifications were reconciled against actual receipts. Human return required fresh capacity and capture-health checks; an expiring passive collector was renewed separately from the unchanged query budget. The first collector stop did not exit promptly, so the supervisor stopped only the identity-verified owned collector and retained its prior CSVs before starting the replacement. The capture gap remains a recorded operational event.

These changes have focused fixture and private independent-review support. Their live application effect still requires new bounded observations. Selection bias, a single host, cooperative agents and private-only reproducibility remain limitations; successful preparation is not a successful calibration.
