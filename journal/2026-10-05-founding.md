# Founding record — 2026-10-05

Status: public-safe design record; no launcher implementation or efficiency result yet.

An operator working with several terminal AI tools asked for a supervisor, evaluator/advisor,
curator/researcher and a context-preserving executor fork, alongside an independent human recovery
terminal. The operator then clarified that the approach must serve **any project**, with the
ongoing AI-visibility project only a worked example, and that public material must omit personal
data and credentials. The supervisor was authorized to design parallel versus sequential work.

We chose a generic coordination core and project adapters. Independent review and research can
run alongside implementation; contested writes and machine control must serialize. Terminal titles
are useful but insufficient identity. Captured native evidence complements visual supervision:
screens can change too quickly to establish a complete record.

Inspection of existing capture methods revealed why format fidelity matters: support memory is
not a conversation transcript; some sources are native JSONL, others database/protobuf; some older
provider entries were stubs. The design consequently requires source labels, immutable private
archives, redacted retrieval derivatives and explicit gaps. A watcher running is not an agent
responding. Forking a conversation is not continuous shared memory or file isolation.

The human-control panel is planned as a graceful drain interface. A request prevents new work,
lets the current bounded phase reach a safe checkpoint and waits for cleanup/ACKs before releasing
the machine. An ETA is not a safety guarantee. Emergency interruption remains a separate action.

The efficiency claim remains a hypothesis. Four roles introduce coordination cost and repeated
context; they may reduce rework and omissions. We will measure cost/usage, duration, quality,
retries and intervention on comparable tasks before making a benefits claim.

Evidence sources: [consulted references](../docs/SOURCES.md), local CLI help and private source-tool
inspection. No private native-session artifacts are included in this entry. High confidence in
the stated design intent; moderate confidence in the proposed operational fit; untested reliability
and efficiency. Confirmation/model-authority bias are reduced by independent reviews and source
checking, but remain possible. Selection/survivorship bias remain in a single-project case study.

Next: role ACKs and critique, isolated fork, capture/mail qualification, ownership/panel tests,
context/budget recovery, notifications and a declared worked-example integration batch. The
technical paper will begin as a protocol, then add results when measured. Public posts will
distinguish plans from demonstrated capabilities.

An initial independent advisor review identified three practical gaps: publishing private Git
history could leak identities despite file redaction; a displayed ownership lease needs enforcement
at each live entry point; expiring provider watches can leave idle models unwatched. We accepted
these findings with limits: fresh public history, shared-lock integration tests and an explicit
awaiting-wake state. The reviewer did not fully trace indirect locks or prove an alternative wake
mechanism, so those remain implementation questions. The curator role has a bounded source
inventory assignment; its capture/wake capabilities are not yet qualified in the new arrangement.

The design scaffold was published with fresh history after a scoped scan of every initial blob
and generic author/committer metadata. No private project history was transferred. A first executor
launch check then confirmed a distinct fork session, its parent, the intended model and a clean
separate worktree. The executor acknowledged its new role and waited without starting external
work. Confidence is high in these observed startup facts; unattended coordination, reliable wake
and safe-pause behavior remain untested. This single launch is not a portable launcher result.
